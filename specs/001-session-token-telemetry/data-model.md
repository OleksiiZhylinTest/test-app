# Data Model: Agentic SDLC Token Consumption Telemetry

**Branch**: `001-session-token-telemetry` | **Date**: 2026-06-05

## Entities

### Session

Represents a single Claude Code interaction from start to stop.

| Field | Type | Description |
|-------|------|-------------|
| `session_id` | `str` | Unique identifier provided by Claude Code in the Stop hook JSON; used as the report file name prefix (first 8 chars). |
| `transcript_path` | `Path` | Absolute path to the JSONL transcript file for this session. |
| `project` | `str` | Directory name of the working project (`cwd` basename). |
| `branch` | `str` | Git branch active at session start (read from first `gitBranch` field in transcript). |
| `turns` | `list[Turn]` | Ordered list of turns, one per user prompt. |

**Constraints**:
- One session maps to exactly one report file.
- The report file is overwritten (not appended) if the session ID matches an existing file.
- Sessions with zero turns produce no report file.

---

### Turn

A segment of a session bounded by consecutive user prompts.

| Field | Type | Description |
|-------|------|-------------|
| `timestamp` | `str` | ISO-8601 timestamp of the user prompt that opened this turn. |
| `prompt` | `str` | Truncated excerpt (≤70 chars) of the user prompt text. |
| `steps` | `list[Step]` | Ordered list of API call steps within this turn. |

**Constraints**:
- User entries whose content consists entirely of `tool_result` blocks do not open a new turn.
- A turn with zero steps is valid (e.g., system-only messages) but contributes no token totals.

---

### Step

A single API call within a turn. One step may cover multiple tool invocations issued in the same API call.

| Field | Type | Description |
|-------|------|-------------|
| `timestamp` | `str` | ISO-8601 timestamp of the first assistant entry in this step. |
| `usage` | `TokenUsage` | Token counts for this API call. |
| `model` | `str \| None` | Model identifier (e.g., `claude-sonnet-4-6`). |
| `stop_reason` | `str \| None` | API stop reason (e.g., `tool_use`, `end_turn`). |
| `operations` | `list[Operation]` | Tool invocations within this step (may be empty for pure text responses). |

**Grouping rule**: Consecutive assistant JSONL entries with identical `(input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens)` belong to the same step.

---

### TokenUsage

Token counts attached to one API call.

| Field | Type | Description |
|-------|------|-------------|
| `input_tokens` | `int` | Fresh (uncached) input tokens sent to the model. |
| `cache_creation_input_tokens` | `int` | New context written to the prompt cache in this call. |
| `cache_read_input_tokens` | `int` | Context served from the cache (cheaper than fresh input). |
| `output_tokens` | `int` | Tokens generated by the model in this call. |

---

### Operation

A single tool invocation within a step.

| Field | Type | Description |
|-------|------|-------------|
| `tool` | `str` | Tool name as reported by the API (e.g., `Read`, `Bash`, `Agent`). |
| `input` | `dict` | Raw input arguments for the tool call. |

**Display label rules** (for report rendering):

| Tool | Label format |
|------|-------------|
| `Agent` | `**→ {subagent_type}**: {description[:55]}` |
| `Read` | `Read({filename})` |
| `Write` | `Write({filename})` |
| `Edit` | `Edit({filename})` |
| `Bash` | `Bash: "{description or command[:55]}"` |
| `Glob` | `Glob({pattern})` |
| `Grep` | `Grep("{pattern}")` |
| `TaskCreate` | `TaskCreate({subject[:40]})` |
| `TaskUpdate` | `TaskUpdate(#{taskId})` |
| `TaskGet` / `TaskList` | tool name only |
| *(other)* | tool name only |

---

### Token Report (output artifact)

The generated Markdown file.

| Property | Value |
|----------|-------|
| Location | `generated/debug/claude_session_{session_id[:8]}.md` |
| Format | GitHub-Flavored Markdown |
| Lifecycle | Overwritten each time the same session ID generates a report |
| Sections | Header, Session Totals, Turn Details, Hotspots (conditional) |

**Hotspots section**: included only when at least one step has `cache_creation_input_tokens > 0`. Lists the top 5 steps ranked by `cache_creation_input_tokens` descending.

## State Transitions

```
transcript JSONL (source)
      │
      ▼
[_load_transcript] — deduplicate by uuid
      │
      ▼
[_parse_turns]
  ├─ user entry (tool_result only) ──→ skip
  ├─ user entry (real prompt) ──→ open new Turn
  └─ assistant entry
       ├─ same usage fingerprint as current step ──→ append operations to current Step
       └─ different fingerprint ──→ flush current Step, open new Step
      │
      ▼
[_render_markdown] ──→ Token Report file
```
